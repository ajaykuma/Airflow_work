# Apache Airflow 2.8.1 Setup with PostgreSQL and LocalExecutor
# CentOS Stream 9 / Python 3.9
# ------------------------------------------------------------
# Purpose:
# Install Apache Airflow 2.8.1 in a Python virtual environment,
# configure PostgreSQL as the metadata database, use LocalExecutor,
# create an Airflow Admin user, and start the scheduler/webserver.
#
# Tested lab configuration:
#   OS          : CentOS Stream 9
#   Python      : 3.9
#   Java        : OpenJDK 11
#   Airflow     : 2.8.1
#   PostgreSQL  : 16.x
#   Executor    : LocalExecutor
#   AIRFLOW_HOME: /home/hdu/airflow
#
# IMPORTANT:
# - Run commands as the appropriate user.
# - Commands requiring root privileges use sudo.
# - Replace <...> placeholders with your own values.
# - This is a lab/development setup, not a production deployment.
# - Keep PostgreSQL credentials and Airflow UI credentials separate.
# - Do not copy real passwords into shared instruction files.

============================================================
8. INSTALL AND CONFIGURE POSTGRESQL
============================================================

# Check available PostgreSQL versions on CentOS Stream 9
sudo dnf module list postgresql

# Example: enable PostgreSQL 16
sudo dnf module enable postgresql:16

# Install server and useful extensions
sudo dnf install -y postgresql-server postgresql-contrib

# Initialize the database cluster
sudo postgresql-setup --initdb

# Start PostgreSQL and enable it at boot
sudo systemctl enable --now postgresql

# Check service
sudo systemctl status postgresql

# Verify PostgreSQL is listening on port 5432
sudo ss -lntp | grep 5432


============================================================
9. CREATE AIRFLOW DATABASE AND POSTGRESQL USER
============================================================

# Open PostgreSQL as the postgres OS/database administrator
sudo -u postgres psql

# Run inside psql:

CREATE DATABASE airflow;
CREATE USER airflow WITH PASSWORD '<POSTGRES_AIRFLOW_PASSWORD>';
GRANT ALL PRIVILEGES ON DATABASE airflow TO airflow;

\q

# Example lab password can be "airflow", but use a stronger password
# when appropriate.


============================================================
10. CONFIGURE POSTGRESQL AUTHENTICATION
============================================================

# Find pg_hba.conf
sudo -u postgres psql -c "SHOW hba_file;"

# Back up the file
sudo cp /var/lib/pgsql/data/pg_hba.conf \
        /var/lib/pgsql/data/pg_hba.conf.backup

# Inspect active rules
sudo grep -v '^#' /var/lib/pgsql/data/pg_hba.conf | grep -v '^$'

# Edit:
sudo vi /var/lib/pgsql/data/pg_hba.conf


------------------------------------------------------------
Recommended local lab configuration
------------------------------------------------------------

# Keep local Unix-socket access for the postgres administrator
# using peer authentication:

local   all             all                                     peer

# Use password authentication for TCP localhost connections:

host    all             all             127.0.0.1/32            scram-sha-256
host    all             all             ::1/128                 scram-sha-256

# Keep the replication rules generated by PostgreSQL unless you
# have a specific reason to change them.


------------------------------------------------------------
IMPORTANT
------------------------------------------------------------

# Do NOT change:
#
#   local all all peer
#
# to password authentication unless there is a specific reason.
#
# Keeping peer authentication allows:
#
#   sudo -u postgres psql
#
# to work without requiring a postgres database password.

# Reload PostgreSQL after changing pg_hba.conf:
sudo systemctl reload postgresql

============================================================
12. GRANT AIRFLOW SCHEMA PRIVILEGES
============================================================

# Airflow must be able to create its metadata tables.
# PostgreSQL 15/16 installations may require explicit privileges
# on the public schema.

sudo -u postgres psql

# Run:

ALTER DATABASE airflow OWNER TO airflow;

\c airflow

GRANT ALL ON SCHEMA public TO airflow;
ALTER SCHEMA public OWNER TO airflow;

\q

# This ensures the Airflow database user can create tables in
# the public schema.


============================================================
13. CONFIGURE AIRFLOW TO USE POSTGRESQL
============================================================

# Check current database configuration:
airflow config get-value database sql_alchemy_conn

# Edit:
vi /home/hdu/airflow/airflow.cfg

# Change the default SQLite setting:
#
# sql_alchemy_conn = sqlite:////home/hdu/airflow/airflow.db
#
# to PostgreSQL:

sql_alchemy_conn = postgresql+psycopg2://airflow:<POSTGRES_AIRFLOW_PASSWORD>@localhost:5432/airflow

# Verify:
airflow config get-value database sql_alchemy_conn


============================================================
14. CHANGE EXECUTOR TO LOCALEXECUTOR
============================================================

# Check current executor:
airflow config get-value core executor

# Edit:
vi /home/hdu/airflow/airflow.cfg

# Change:
#
# executor = SequentialExecutor
#
# to:

executor = LocalExecutor

# Verify:
airflow config get-value core executor

# Expected:
# LocalExecutor


------------------------------------------------------------
Why LocalExecutor?
------------------------------------------------------------

# SequentialExecutor is limited to sequential task execution and
# is mainly suitable for simple/local SQLite usage.
#
# LocalExecutor allows multiple Airflow tasks to run concurrently
# on the same machine and works with PostgreSQL.


============================================================
15. MIGRATE / INITIALIZE AIRFLOW METADATA DATABASE
============================================================

# Airflow 2.8.1 recommends `db migrate`.
# `db init` is deprecated.

airflow db migrate

# Expected successful output includes:
#
# DB: postgresql+psycopg2://airflow:***@localhost:5432/airflow
# Context impl PostgresqlImpl.
# Will assume transactional DDL.
# Database migrating done!

# If you receive:
#
#   psycopg2.errors.InsufficientPrivilege:
#   permission denied for schema public
#
# return to Section 12 and grant ownership/privileges on schema public.

24. COMMON PROBLEMS AND FIXES
============================================================

PROBLEM 1: Wrong Airflow constraint file
------------------------------------------------------------
Symptom:
Installation fails or dependency resolution behaves unexpectedly.

Fix:
Use the constraint file matching Python:

Python 3.9:
https://raw.githubusercontent.com/apache/airflow/constraints-2.8.1/constraints-3.9.txt

Python 3.8:
https://raw.githubusercontent.com/apache/airflow/constraints-2.8.1/constraints-3.8.txt


PROBLEM 2: Ident authentication failed
------------------------------------------------------------
Symptom:
FATAL: Ident authentication failed for user "airflow"

Cause:
PostgreSQL TCP localhost connections are using ident authentication.

Fix:
In pg_hba.conf use:

host    all    all    127.0.0.1/32    scram-sha-256
host    all    all    ::1/128         scram-sha-256

Then:
sudo systemctl reload postgresql


PROBLEM 3: Peer authentication failed
------------------------------------------------------------
Symptom:
FATAL: Peer authentication failed for user "airflow"

Cause:
The connection is using a Unix socket and PostgreSQL expects
the operating-system username to match the database username.

Fix:
For Airflow testing, use TCP explicitly:

psql -h 127.0.0.1 -U airflow -d airflow

Keep:
local   all   all   peer

for normal postgres administrator access.


PROBLEM 4: sudo -u postgres psql asks for a password
------------------------------------------------------------
Cause:
The local peer authentication rule was changed.

Fix:
Restore:

local   all   all   peer

Then reload:

sudo systemctl reload postgresql

Test:

sudo -u postgres psql


PROBLEM 5: permission denied for schema public
------------------------------------------------------------
Symptom:
psycopg2.errors.InsufficientPrivilege:
permission denied for schema public

Fix:

sudo -u postgres psql

ALTER DATABASE airflow OWNER TO airflow;
\c airflow
GRANT ALL ON SCHEMA public TO airflow;
ALTER SCHEMA public OWNER TO airflow;

\q

Then:

airflow db migrate


PROBLEM 6: Port 8080 already in use
------------------------------------------------------------
Find the process:

sudo ss -lntp | grep 8080

Stop the old Airflow webserver if appropriate, or use another port:

airflow webserver --port 8081


PROBLEM 7: Airflow UI login password forgotten
------------------------------------------------------------
Reset it:

airflow users reset-password --username airflow

The PostgreSQL password does not determine the Airflow UI password.


============================================================
25. IMPORTANT NOTES ABOUT SQLITE AND POSTGRESQL
============================================================

# An initial Airflow installation may create:
#
#   /home/hdu/airflow/airflow.db
#
# when SQLite is used.

# After changing sql_alchemy_conn to PostgreSQL, Airflow uses PostgreSQL
# for its metadata database.

# The existing SQLite metadata is NOT automatically copied into
# PostgreSQL by `airflow db migrate`.

# Therefore, if this was only a fresh lab installation, the old
# SQLite file can simply be retained as a backup/reference.
#
# Do NOT delete it until you are certain it is no longer required.
